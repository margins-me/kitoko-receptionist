# PayPal JS SDK v6 on the deposit page (`/pay/[id]`)

Checked against developer.paypal.com (Set up JavaScript SDK v6, PayPal checkout v6) and the types shipped in
`@paypal/paypal-js@11.3.0` (`apps/web`), October 2026. Sandbox only.

## 1. Load the core script

`@paypal/paypal-js@11.3.0` has a v6 loader under the `sdk-v6` subpath:

```ts
import { loadCoreSdkScript } from "@paypal/paypal-js/sdk-v6";

const paypal = await loadCoreSdkScript({ environment: "sandbox" }); // null on the server
```

It injects `https://www.sandbox.paypal.com/web-sdk/v6/core` (retries, dedupes concurrent loads) and resolves to
`window.paypal`. Run it in a client component's effect. Types (`SdkInstance`, `OneTimePaymentSession`,
`OnApproveDataOneTimePayments`…) come from the same subpath.

## 2. Create the instance with the client id

The current docs authenticate standard checkout (PayPal, Pay Later, cards) with the **client id**. No client token is
needed. The client token (`POST /v1/oauth2/token` with `response_type=client_token`, `domains[]`) is now documented
as "for Fastlane only".

```ts
const sdk = await paypal.createInstance({
  clientId: process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID!,
  components: ["paypal-payments"],
  pageType: "checkout",
  locale: "fr-FR", // BCP-47; en-GB for en
});
```

## 3. Check eligibility, then render the web components

```ts
const methods = await sdk.findEligibleMethods({ currencyCode: "EUR" }); // or "GBP"
if (methods.isEligible("paypal")) { /* render <paypal-button type="pay"> */ }
if (methods.isEligible("paylater")) {
  const { countryCode, productCode } = methods.getDetails("paylater");
  // render <paypal-pay-later-button> with countryCode/productCode set as properties
}
```

The buttons are custom elements (`<paypal-button>`, `<paypal-pay-later-button>`). React 19 renders custom elements;
set `countryCode` / `productCode` through a ref.

## 4. One session per button; start it on click

```ts
const session = sdk.createPayPalOneTimePaymentSession({ onApprove, onCancel, onError });
// Pay Later: sdk.createPayLaterOneTimePaymentSession({ onApprove, onCancel, onError })

button.addEventListener("click", () => {
  // Do NOT await createOrder() before start(): it breaks the click's transient activation (popup blocked).
  session.start({ presentationMode: "auto" }, createOrder());
});
```

- `createOrder()` returns `Promise<{ orderId: string }>`. It calls **our** server, which runs
  `@kitoko/paypal` `createOrder` (amounts from the booking row, never from the browser) and returns `{ orderId }`.
  If the booking already has a `created` payment, return its order id.
- `presentationMode`: `"auto"` (popup, falls back to modal), `"popup"`, `"modal"`, `"redirect"`,
  `"payment-handler"`. With `"redirect"`, call `session.hasReturned?.()` and `session.resume?.()` on page load.

## 5. Capture on the server

```ts
async function onApprove({ orderId, payerId }: OnApproveDataOneTimePayments) {
  await fetch(`/api/pay/${bookingId}/capture`, { method: "POST", body: JSON.stringify({ orderId }) });
}
```

Server: `captureOrder({ orderId })` (request id `capture-{orderId}`, the same key as the webhook backstop). Then
`paypal_capture_completed(...)`. Results:

- `ok`, status `COMPLETED`: booking confirmed.
- `ok`, status `PENDING`: show "payment pending". `PAYMENT.CAPTURE.COMPLETED` arrives later by webhook.
- `error.code === "declined"` (INSTRUMENT_DECLINED…): ask the client to pay again with another funding source. PayPal
  lets the buyer approve the same order again (its 422 body has a `redirect` link), so `session.start(...)` again with
  the same `{ orderId }`. Untested in sandbox: if PayPal refuses, create a new order (new payment row, new request
  id).
- `error.code === "already_captured"` cannot reach the page: `captureOrder` turns it into the existing capture.

`onCancel({ orderId })`: keep the hold and show the button again. `onError(err)`: log `err.code`, show a generic
message.

## Without JavaScript and with `PAYPAL_ENV=fake`

`createOrder` also returns `approveUrl` (the `payer-action` link). A plain link to it is the no-JS fallback. PayPal
redirects to `return_url?token={orderId}&PayerID=…`; capture there. With `PAYPAL_ENV=fake`, `approveUrl` is
`${SITE_URL}/pay/fake-approve?token={orderId}`. Use that link instead of the SDK buttons: the v6 script cannot talk to
the fake.
